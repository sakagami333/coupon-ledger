# 検定クーポン台帳（coupon-ledger）

検定クーポンの発行・確認・削除を、Pull Request（PR）で非同期にダブルチェックするための台帳リポジトリです。
発行や削除は、SharePoint で配っている `coupon-tool.html` から行います。
ツールのソースはこのリポジトリの `tool/coupon-tool.html` で管理し、更新したら SharePoint のファイルを差し替えます。

## 流れ

```
発行者：発行リストを作って「まとめて発行」──→ PR が1つ自動で作られる（確認待ち）
                              │
確認者：GitHub で PR を確認（都合のよいときに）
        ├ OK → Approve
        │       └→ 発行者：ツールの一覧で「マージして確定」→ お客様へ送付
        └ NG → Request changes でコメント（差し戻し）
                └→ 発行者：ツールで「取り下げ」→ 正しい内容で発行し直す
```

- 1クーポン＝1ファイルです（`coupons/発行年/コード.json`）。main にあるファイルが「確定」したクーポンです。
- 複数の受検日・複数の配布先・複数の検定を、まとめて1つの PR で発行できます（1回 50 件まで）。確認・確定・取り下げは PR 単位です。
- 削除も同じ流れです。ツールで「削除申請」→ 確認者が Approve → 発行者が「マージして確定」すると削除されます。
- 同じ「受検日・組織名・検定」のクーポンは1枚だけです。確認待ちのものも含めてツールがチェックします。

---

## 確認者の方へ（部内の誰でも確認者になれます）

1. GitHub から届く通知、または発行者から送られた PR のリンクを開きます。
2. PR の本文にある表（1行＝1クーポン。コード・検定・受検日・有効期限日・配布先・区分・利用者数など）を、依頼内容（メール・チャットなど）と見比べます。
3. 結果を送ります。
   - **問題なし：** 「Files changed」タブ →「Review changes」→ **Approve** →「Submit review」
   - **誤りあり：** 同じ画面で **Request changes** を選び、何行目がどう違うかを書いて「Submit review」
4. **マージはしないでください。** マージ（確定）は発行者がツールから行います。

> 自分が作った PR は自分で Approve できません（GitHub の仕様）。必ず別の人が確認します。

## 発行者の方へ

1. ツールの「① クーポンを発行する」で、検定・受検日（複数可）・配布先（複数可。組織名ごとに区分と利用者数を入れる）・有効期限日などを入れ、「**発行リストに追加**」を押します。
   - 受検日 2 日 × 配布先 3 社なら、6 件がリストに入ります。
   - 別の検定も続けて追加できます。リストはそのPCに保存されるので、途中で閉じても続きから再開できます。
   - 組織名は Excel などから複数行コピーして貼り付けると、行ごとに分かれて入ります。「組織名」と「利用者数」の2列をコピーすれば、利用者数も一緒に入ります。
   - 有効期限日は、その回に追加するクーポンすべてに付きます。受検日より前の日付にはできません。
2. 発行リストを確認し、「**まとめて発行して確認を依頼する**」を押します。リスト全体で PR が1つ作られます。
   - すでに発行済み・確認待ちのものと同じ組み合わせ（受検日・組織名・検定）は赤く表示され、発行できません。その行を削除してから発行します。
3. 「確認者への依頼文をコピー」を押し、Teams などで確認をお願いします。
4. 承認されると、一覧の状態に「承認：〇〇」と出ます。「**マージして確定（N件）**」を押すと、その PR の全件が確定します。
5. 状態が「**確定**」になったら、「コードをコピー」してお客様へ送付します。

**別システムへの取り込み：** 確定した直後に出る「この N 件の取り込み用CSVをダウンロード」、または一覧の「取り込み用CSV（表示中の確定分）」で出力します（UTF-8・見出し行なし）。
列は「クーポンコード, 割引区分, 割引値, 利用制限数, 有効期限(YYYYMMDD), メモ(検定名 受検日 会社名), メールアドレス制限」です。

**差し戻されたとき：** 一覧で「取り下げ（N件）」を押すと、「発行リストに戻しますか？」と聞かれます。戻すと、間違っている行だけ削除・追加し直して、もう一度まとめて発行できます。

**⚠ 「確定」になるまでは、お客様にコードを送らないでください。**

| 一覧の状態 | 意味 | 発行者がすること |
|---|---|---|
| 確認待ち | 確認者の承認待ち | 待つ。承認されたら「マージして確定」 |
| 差し戻し | 確認者から修正依頼あり | PR のコメントを見て「取り下げ」→ 発行リストに戻して直し、発行し直す |
| 確定 | 送付してよい | コードをコピーして送付 |
| 削除確認待ち | 削除申請中 | 承認されたら「マージして確定」で削除される |
| 取り下げ | 取り下げたもの | 何もしない（このコードは使えません） |

## 管理者向け：リポジトリの設定

### 1. 必要なファイル
- `coupons/config.json`：検定・区分・割引・依頼元の選択肢

### config.json の書き方（割引・メモ用の検定名）
```json
"products": [
  { "code": "scb", "label": "クラウド検定ベーシック", "memoName": "さくらのクラウド検定 ベーシック" }
],
"discounts": [
  { "label": "受験料 100%割引", "type": "percent",    "value": 100 },
  { "label": "受験料 3,000円引き", "type": "fixed_cart", "value": 3000 }
]
```
- `discounts` の `type` は `percent`（割引率）か `fixed_cart`（割引金額）、`value` は割引率（%）または金額（円）です。
- `memoName` は取り込み用CSVのメモに入る検定名です。省略すると `label` が使われます。

### 2. ブランチ保護（GHES・有料プランの場合は必ず設定）
「Settings」→「Branches」（または「Rules」→「Rulesets」）で `main` に次を設定します。

- **Require a pull request before merging**：オン
  - **Required approvals**：1
  - **Dismiss stale pull request approvals when new commits are pushed**：オン
- **Do not allow bypassing the above settings**：オン（管理者も例外にしない）

> github.com の **無料プランの個人 Private リポジトリでは、ブランチ保護が効きません。**
> この場合でも、ツールは「本人以外の Approve があるときだけ」マージボタンを出しますが、GitHub の画面から直接マージすることは止められません。お試し期間は運用ルールで守り、本番（GHES）ではブランチ保護を必ず設定してください。

### 3. マージ後のブランチ削除
ツールがマージ後や取り下げ後に自動で削除します。
「Settings」→「General」→「Automatically delete head branches」もオンにしておくと安心です。

### 4. メンバーの追加
- 「Settings」→「Collaborators」（Organization の場合は Team）から書き込み権限で追加します。
- 各メンバーのトークンに必要な権限は次のとおりです。
  - **classic token：** `repo`
  - **Fine-grained token：** Contents（Read and write）と Pull requests（Read and write）

### 5. 旧形式の台帳について
以前の版（`coupons/coupons-2026.csv` に追記する形式）のデータは、新しいツールでは読み込みません。
お試しのデータだけなら、CSV ファイルを削除してください。
