# 検定クーポン台帳（coupon-ledger）

## このツールは何？

検定クーポンのコード発行・確認・削除のための補助ツールです。
変更内容（新規発行・変更・削除）をリポジトリにPushし、プルリクエストを介して確認者のチェック・承認を受け、記録を残すことができるように設計しました。

発行や削除は、このリポジトリの `docs/index.html`（ブラウザで開くツール）から行います。
ツールは GitHub Pages の URL で開くか、ファイルをダウンロードして開きます（`docs/` フォルダだけを Pages で公開しているため、`coupons/` のクーポンデータは公開されません）。
使い始めるときは、まず下の「[導入手順](#導入手順発行できる状態になるまで)」を行ってください。

## 操作の流れ

```
👤発行者：発行リストを作って「まとめて発行」──→ PR が1つ自動で作られる（確認待ち）
・確認者をReviewerに設定（自動で行われないので）
・Slackで確認依頼を提出（確認者を必ずメンションする）
                              │
👤確認者：GitHub で PR を確認（都合のよいときに）
        ├ OK → Approve
        │       └→ 発行者：ツールの一覧で「マージして確定」→ お客様へ送付
        └ NG → Request changes でコメント（差し戻し）
                └→ 発行者：ツールで「取り下げ」→ 正しい内容で発行し直す
```
補足事項：
- 1クーポン＝1ファイルで、**検定ごとのフォルダ**に保存します（`coupons/検定のid/コード.json`）。main にあるファイルが「確定」したクーポンです。
  - 検定に当てはまらない古い試験データは `coupons/_unassigned/` にあります。
- 複数の受検日・複数の配布先・複数の検定を、まとめて1つの PR で発行できます（1回 50 件まで）。確認・確定・取り下げは PR 単位です。
- 削除も同じ流れです。ツールで「削除申請」→ 確認者が Approve → 発行者が「マージして確定」すると削除されます。
- 同じ「受検日・組織名・検定」のクーポンは1枚だけです。確認待ちのものも含めてツールがチェックします。

## 導入手順（発行できる状態になるまで）

1人あたり 10〜15 分ほどです。確認だけする人は、手順 1〜2 だけで大丈夫です。

### 用意するもの
- GitHub のアカウント（ない場合は https://github.com で作成）
- パソコンのブラウザ（Google Chrome または Microsoft Edge）

### 1. リポジトリに招待してもらう
1. 管理者に、自分の GitHub ユーザー名を伝えます。
2. GitHub から届く招待メールの「**View invitation**」→「**Accept invitation**」を押します。
   - メールが見当たらないときは、https://github.com/sakagami333/coupon-ledger を開くと、画面上部に招待の案内が出ます。
3. https://github.com/sakagami333/coupon-ledger が開ければ OK です。

### 2. アクセストークンを作る
ツールがあなたの代わりに GitHub を操作するための「合い鍵」です。**他の人と共有しないでください。**

1. GitHub 右上のアイコン →「**Settings**」→ 左メニュー一番下の「**Developer settings**」を開きます。
2. 「**Personal access tokens**」→「**Tokens (classic)**」→「**Generate new token**」→「**Generate new token (classic)**」を押します。
3. 次のとおり入力します。
   | 項目 | 入力内容 |
   |---|---|
   | Note | `coupon-tool`（何でもよい） |
   | Expiration | `90 days` |
   | Select scopes | **repo** にチェック（ほかは不要） |
4. 一番下の「**Generate token**」を押し、表示された `ghp_…` で始まる文字列を**コピー**します。
   - この画面を閉じると二度と表示されません。コピーし忘れたら作り直してください。

> **Fine-grained token を使わない理由：** このリポジトリは個人アカウントにあるため、招待されたメンバーは Fine-grained token でこのリポジトリを選べません。Organization（GHES など）に移したあとは、Fine-grained token（Contents と Pull requests を Read and write）に切り替えられます。

### 3. ツールを開けるようにする
どちらか一方を行います。**GitHub Pages が公開されている場合は A** がおすすめです（更新が自動で届き、トークンもそのサイト専用の場所に保存されます）。

**A. GitHub Pages の URL で開く**
1. 管理者から案内された URL（例：`https://sakagami333.github.io/coupon-ledger/`）を Chrome または Edge で開きます。
2. ブックマークしておきます。

**B. ファイルをダウンロードして開く（Pages が使えない場合）**
1. https://github.com/sakagami333/coupon-ledger/blob/main/docs/index.html を開きます。
2. ファイル表示の右上にある **ダウンロードボタン（⤓「Download raw file」）** を押します。
3. ダウンロードした `index.html` を `coupon-tool.html` など分かりやすい名前に変え、分かりやすい場所に移します（例：`ドキュメント\coupon-tool\`）。
4. ファイルを右クリック →「その他のオプションを確認」→「送る」→「**デスクトップ（ショートカットを作成）**」で、デスクトップにショートカットを作ります。

> 「Raw」ボタンで開いた画面を「名前を付けて保存」しても構いません。GitHub の通常のファイル表示画面をそのまま保存すると、ツールとして動かないので注意してください。

### 4. ツールを開いて設定する
1. A ならブックマーク、B ならデスクトップのショートカットから開きます。
   - B で Chrome / Edge 以外（メモ帳など）で開いてしまう場合は、右クリック →「プログラムから開く」→ Chrome または Edge を選びます。
2. 「**⚙ 設定**」タブを開き、次のとおり入力します。

   | 項目 | 入力内容 |
   |---|---|
   | API の URL | `https://api.github.com` |
   | オーナー（組織名） | `sakagami333` |
   | リポジトリ名 | `coupon-ledger` |
   | ブランチ | `main` |
   | クーポンを置くフォルダ | `coupons` |
   | 選択肢の設定ファイル | `coupons/config.json` |
   | 個人アクセストークン | 手順 2 でコピーした `ghp_…` |

3. 「**保存して接続テスト**」を押します。
4. 緑色で「✓ 保存しました。『（あなたの名前）』として sakagami333/coupon-ledger に接続できました。」と出て、画面右上に自分の名前が表示されれば完了です。

設定とトークンはそのパソコンのブラウザにだけ保存されます。別のパソコンや別のブラウザで使うときは、手順 3〜4 をもう一度行ってください。

### 5. 動作を確認する（任意）
1. 「① クーポンを発行する」で、検定などのプルダウンに実際の選択肢（クラウド検定ベーシック など）が出ていることを確認します。
2. メモに「テスト」と入れて 1 件だけ発行リストに追加し、「まとめて発行して確認を依頼する」を押します。
3. 「② 発行済み一覧・確認状況」に「確認待ち」で出たら、「取り下げ」を押して片付けます（発行リストには戻さなくて OK）。

### うまくいかないとき

| 表示されるメッセージ | 原因と対処 |
|---|---|
| ログイン確認に失敗しました（401） | トークンが間違っているか期限切れです。手順 2 で作り直して貼り直してください |
| リポジトリ「…」が見つかりません（404） | オーナー名・リポジトリ名の入力ミスか、招待をまだ承認していません（手順 1） |
| このリポジトリへの書き込み権限がありません | 管理者に、書き込み権限で招待されているか確認してもらってください |
| トークンに「Pull requests」の権限がありません | classic token なら `repo` にチェックが入っているか確認してください |
| 次の項目が空欄です（赤枠の欄） | 薄い文字は入力例です。赤枠の欄に実際の値を入れてください |
| 「このブラウザには、ツールの設定（トークンなど）が保存されていません」／検定の欄が「設定がないため読み込めません」「GitHub に未接続のため読み込めません」になる／右上に自分の名前が出ていない | GitHub に接続できていません。設定が消えていることが多いです（下の「キャッシュや Cookie を消したら…」を参照） |

### ツールが更新されたとき
- **A（Pages の URL）で使っている場合：** 何もしなくて大丈夫です。ページを再読み込み（F5）すれば新しい版になります。
- **B（ダウンロード）で使っている場合：** 手順 3-B と同じ方法で新しいファイルをダウンロードし、**同じ場所に同じ名前で上書き保存**してください。設定とトークンはブラウザに残っているので、入れ直しは不要です。

> A と B では設定の保存場所が別です。B から A に切り替えたときは、A の画面で手順 4 の設定をもう一度行ってください。

### トークンの期限が切れたとき（90 日ごと）
接続テストや発行で「401」が出たら、手順 2 でトークンを作り直し、手順 4 の「個人アクセストークン」だけ貼り直して「保存して接続テスト」を押します。

### キャッシュや Cookie を消したら、検定が選べなくなったとき
ブラウザの「閲覧履歴データの削除」で **「Cookie と他のサイトデータ」** を消すと、**このツールの設定（トークンを含む）も一緒に消えます**。設定はブラウザの中（localStorage）に保存しているためです。

**こうなります**
- 画面の上に赤い枠で「このブラウザには、ツールの設定（トークンなど）が保存されていません。」と表示される（枠の中のボタンで設定タブを開けます）
- 画面右上に自分の名前（例：`Kimi Sakagami @sakagami333`）が出ない
- 検定の欄が「登録済みの検定がありません」「GitHub に未接続のため読み込めません」になる
- 設定タブを開くと、オーナー名・リポジトリ名・トークンが空になっている

これは `config.json` やツールの不具合ではありません。

**直し方**
1. 設定タブで、手順 4 のとおりオーナー名・リポジトリ名を入れ直します。
2. トークンは GitHub では作った直後にしか表示されないので、控えがなければ手順 2 で**作り直します**（古いトークンは GitHub の Settings → Developer settings → Personal access tokens で削除しておくと安全です）。
3. 「保存して接続テスト」を押し、右上に自分の名前が出れば元どおりです。

**消さないようにするには**
- 別のサイトの不具合でデータを消したいときは、**そのサイトのデータだけ**を消します（そのサイトを開いた状態で、アドレスバー左のアイコン →「サイトの設定」または「Cookie とサイトデータ」から削除）。
- 「閲覧履歴データの削除」を使うときは、**「キャッシュされた画像とファイル」だけ**にチェックを入れれば、設定は残ります。
- 念のため、下の「設定を別の開き方へ移す」の手順 1 で設定をコピーし、安全な場所に控えておくと、入れ直しが楽になります（トークンが含まれるので、共有フォルダやチャットには貼らないでください）。

### Tips：設定が白紙になった・設定がどこにあるか分からないとき

#### 設定はどこに保存されている？
設定タブの内容（API の URL・オーナー・リポジトリ名・トークンなど）は、ファイルではなく**ブラウザの中（localStorage という保存領域）**に保存されています。GitHub や SharePoint には保存されません。

保存先は **「ブラウザ」×「ツールを開いたアドレス」ごとに別々**です。次のような場合は、別のツールとして扱われ、設定は白紙の状態から始まります。

| 白紙になる例 | 理由 |
|---|---|
| ダウンロードしたファイルで使っていたが、Pages の URL で開いた（またはその逆） | 開いたアドレスが違う（`file://…` と `https://…github.io/…`） |
| Chrome で設定したが、Edge で開いた／Chrome の別のプロファイルで開いた | ブラウザ（プロファイル）が違う |
| 別のパソコンで開いた | パソコンが違う |
| ブラウザの「閲覧履歴データの削除」で Cookie やサイトデータを消した | 保存領域ごと消えた |

> ツールの更新（新しい版への差し替え）や Ctrl＋F5 での再読み込みでは、設定は消えません。

**白紙になっていても、ブランチ（`main`）・クーポンを置くフォルダ（`coupons`）・選択肢の設定ファイル（`coupons/config.json`）だけは入っています。** これはツールの初期値です。この状態なら「このアドレス・このブラウザでは、まだ一度も保存していない」という意味なので、手順 4 のとおり入力して「保存して接続テスト」を押してください。

#### 保存されている設定を確認する（開発者ツール）
1. 設定したときと同じブラウザで、同じアドレス（Pages の URL、またはダウンロードしたファイル）のツールを開きます。
2. キーボードの **F12** を押して、開発者ツールを開きます。
3. 上のタブから「**Application**」（日本語表示では「アプリケーション」）を選びます。見当たらないときは「»」の中にあります。
4. 左の「Storage」→「**Local Storage**」を開き、ツールのアドレス（`https://sakagami333.github.io` や `file://`）を選びます。
5. 右側に次の項目が表示されます。

   | キー | 中身 |
   |---|---|
   | `coupon.settings` | 設定タブの内容（トークンを含む） |
   | `coupon.cart` | 発行リストの中身（まだ発行していないもの） |
   | `coupon.blob:…` | 一覧を速く表示するための一時データ（消しても問題ありません） |

6. 確認が終わったら、F12 をもう一度押して開発者ツールを閉じます。

#### 設定を別の開き方へ移す（例：ダウンロード版 → Pages 版）
手で入れ直すのがいちばん確実ですが、次の方法でコピーもできます。
1. **移す元**のツールを開き、F12 →「**Console**」（コンソール）タブを開いて、次を入力して Enter を押します。設定がクリップボードにコピーされます。
   ```js
   copy(localStorage.getItem('coupon.settings'))
   ```
2. **移す先**のツールを開き、F12 →「Console」で次を入力し、`ここに貼り付け` の部分を Ctrl＋V で貼り付けた内容に置き換えて Enter を押します。
   ```js
   localStorage.setItem('coupon.settings', 'ここに貼り付け')
   ```
3. F5 で再読み込みすると、設定が入った状態になります。

> - コンソールに貼り付けようとすると「貼り付けを許可するには allow pasting と入力してください」と表示されることがあります。その場合は `allow pasting` と入力して Enter を押してから、もう一度貼り付けてください。
> - コピーした内容には**トークンが含まれます**。チャットやメールに貼ったり、人に渡したりしないでください。
> - 発行リストも移したいときは、同じ手順で `coupon.settings` を `coupon.cart` に変えて行います。

## 確認者の方へ（部内の誰でも確認者になれます）

1. GitHub から届く通知、または発行者から送られた PR のリンクを開きます。
2. PR の本文にある表（1行＝1クーポン。コード・検定・受検日・有効期限日・配布先・区分・利用者数など）を、依頼内容（メール・チャットなど）と見比べます。
3. 結果を送ります。
   - **問題なし：** 「Files changed」タブ →「Review changes」→ **Approve** →「Submit review」
   - **誤りあり：** 同じ画面で **Request changes** を選び、何行目がどう違うかを書いて「Submit review」
4. **マージはしないでください。** マージ（確定）は発行者がツールから行います。

> 自分が作った PR は自分で Approve できません（GitHub の仕様）。必ず別の人が確認します。

## 発行者の方へ

1. ツールの「① クーポンを発行する」で、**登録済みの検定を選び**、配布先（複数可。組織名ごとに区分と利用者数を入れる）などを入れて、「**発行リストに追加**」を押します。
   - 検定を選ぶと、受検日と有効期限日が自動で入ります（変更できません）。複数日開催の検定は、発行する受検日だけにチェックを入れます。
   - 選びたい検定が一覧にないときは、管理者に登録を依頼してください（下の「検定の登録」）。
   - 受検日 2 日 × 配布先 3 社なら、6 件がリストに入ります。
   - 別の検定も続けて追加できます。リストはそのPCに保存されるので、途中で閉じても続きから再開できます。
   - 組織名は Excel などから複数行コピーして貼り付けると、行ごとに分かれて入ります。「組織名」と「利用者数」の2列をコピーすれば、利用者数も一緒に入ります。
2. 発行リストを確認し、「**まとめて発行して確認を依頼する**」を押します。リスト全体で PR が1つ作られます。
   - **コードが決まっている場合（パートナー企業など、営業部のツールで作成済みのコード）：** 発行リストの「コード（指定がある場合）」欄に入力します。空欄の行は自動で作られます。
     - 営業部のツールからコードを縦に並べてコピーし、1行目の欄に貼り付けると、上から順に入ります。
     - 使える文字は英数字・`-`・`_`（3〜64文字）です。発行済みのコードやリスト内で重複するコードは赤く表示され、発行できません。
     - PR の表では「📌指定」と表示されるので、確認者は依頼のコードと一致しているかも確認します。
   - すでに発行済み・確認待ちのものと同じ組み合わせ（受検日・組織名・検定）は赤く表示され、発行できません。その行を削除してから発行します。
3. 「確認者への依頼文をコピー」を押し、Teams などで確認をお願いします。
4. 承認されると、一覧の状態に「承認：〇〇」と出ます。「**マージして確定（N件）**」を押すと、その PR の全件が確定します。
5. 状態が「**確定**」になったら、「コードをコピー」してお客様へ送付します。

**別システムへの取り込み（検定ごとにまとめて抽出）：** 「② 発行済み一覧・確認状況」で検定を選び、取り込み用CSVを出力します（UTF-8・見出し行なし）。
1. 検定の絞り込みで、抽出する検定を選びます。一覧の上に「この検定：確定 N 件（未抽出 M 件）・確認待ち K 件・前回の抽出」が表示されます。
2. 状態の絞り込みを「**確定（未抽出）**」にすると、まだ抽出していない確定分だけが表示されます。ふだんはこの状態で出力します。
3. 「**取り込み用CSV（表示中の確定分）**」を押します。出力前に件数の確認が出ます。
   - 抽出済みのクーポンが含まれているときや、その検定に確認待ち・差し戻しが残っているときは、確認画面で注意が表示されます（未確定の分は CSV に含まれません）。
- 抽出すると「いつ・誰が・何件」の記録が残り、一覧の状態欄にも「抽出済 11/25」のように表示されます。
- 確定した直後に出る「この N 件の取り込み用CSVをダウンロード」で出力した場合も、同じように記録されます。

**差し戻されたとき：** 一覧で「取り下げ（N件）」を押すと、「発行リストに戻しますか？」と聞かれます。戻すと、間違っている行だけ削除・追加し直して、もう一度まとめて発行できます。

**⚠ 「確定」になるまでは、お客様にコードを送らないでください。**

| 一覧の状態 | 意味 | 発行者がすること |
|---|---|---|
| 確認待ち | 確認者の承認待ち | 待つ。承認されたら「マージして確定」 |
| 差し戻し | 確認者から修正依頼あり | PR のコメントを見て「取り下げ」→ 発行リストに戻して直し、発行し直す |
| 確定 | 送付してよい | コードをコピーして送付 |
| 削除確認待ち | 削除申請中 | 承認されたら「マージして確定」で削除される |
| 取り下げ | 取り下げたもの | 何もしない（このコードは使えません） |

## 管理者向け：リポジトリの設定

### 1. 必要なファイル
- `coupons/config.json`：検定（受検日・期限日）・区分・割引の選択肢

### config.json の書き方（割引・メモ用の検定名）
```json
"products": [
  { "code": "SCB", "label": "クラウド検定ベーシック", "memoName": "クラウド検定 ベーシック" }
],
"discounts": [
  { "label": "受験料 100%割引", "type": "percent",    "value": 100 },
  { "label": "受験料 3,000円引き", "type": "fixed_cart", "value": 3000 }
]
```
- `discounts` の `type` は `percent`（割引率）か `fixed_cart`（割引金額）、`value` は割引率（%）または金額（円）です。
- `code` は検定の種類の略号で、**大文字**（`SCB` / `SCA` / `SAI`）で書きます。クーポンのデータにはこの略号で保存し、画面では `label`（正式名称）に置き換えて表示します。
- `memoName` は取り込み用CSVのメモに入る検定名です。省略すると `label` が使われます。

### 検定の登録（受検日・期限日）
発行画面で選べる検定は、`coupons/config.json` の `exams` に登録します。GitHub の画面で `coupons/config.json` を開き、鉛筆アイコン（Edit）から編集して「Commit changes」します。

```json
"exams": [
  {
    "id": "2026-12-scb",
    "name": "さくらのクラウド検定ベーシック 2026年12月",
    "product": "SCB",
    "round": "2026#12",
    "dates": ["2026-12-10", "2026-12-11"],
    "expires": "2026-12-03"
  }
]
```

| 項目 | 内容 |
|---|---|
| `id` | 検定ごとに重ならない名前（英数字とハイフン。例：`2026-12-scb`） |
| `name` | 発行画面に表示する検定名 |
| `product` | 検定の種類。`products` の `code`（`SCB` / `SCA` / `SAI`）のどれか。クーポンコードの先頭に小文字で使われます（例：`scb261210-…`） |
| `round` | 回次（例：`2026#12`）。クーポンに保存する検定名に使われます |
| `dates` | 受検日（`YYYY-MM-DD`）。複数日開催なら複数書きます |
| `expires` | クーポンの有効期限日（`YYYY-MM-DD`）。**いちばん早い受検日より前**の日付にします（クーポンは申込期間中に使うため） |

- クーポンには、検定名を短い形 **`SCB 2026#12[2026-12-10,11]`**（種類 回次[受検日]）で保存します。2日目以降の受検日は、1日目と違う部分だけを書きます（同じ月なら日だけ、月をまたぐときは `[2026-11-30,12-01]`）。
- メモを空欄で発行すると、配布先ごとに「検定名 - 配布先名」（例：`SCB 2026#12[2026-12-10,11] - 株式会社サンプル`）が入ります。
- 有効期限日を過ぎた検定や、受検日がすべて過ぎた検定は、発行画面に表示されなくなります。古い登録は残しておいても、消しても構いません。
- 書き方に誤りがあると、発行画面の上に赤い文字で、どの検定のどこが違うかが表示されます。
- 複数の検定を並べるときは、`}` と `{` の間にカンマ（`,`）を入れます。JSON の書き方を間違えると選択肢が読み込めなくなるので、保存後にツールを再読み込みして確認してください。

### 2. ブランチ保護（GHES・有料プランの場合は必ず設定）
「Settings」→「Branches」（または「Rules」→「Rulesets」）で `main` に次を設定します。

- **Require a pull request before merging**：オン
  - **Required approvals**：1
  - **Dismiss stale pull request approvals when new commits are pushed**：オン
- **Do not allow bypassing the above settings**：オン（管理者も例外にしない）

> github.com の **無料プランの個人 Private リポジトリでは、ブランチ保護が効きません。**
> この場合でも、ツールは「本人以外の Approve があるときだけ」マージボタンを出しますが、GitHub の画面から直接マージすることは止められません。お試し期間は運用ルールで守り、本番（GHES）ではブランチ保護を必ず設定してください。

### GitHub Pages の公開（ツールの URL を作る）
1. 「Settings」→「Pages」を開きます。
2. 「Build and deployment」の **Source** を「Deploy from a branch」にし、**Branch** を `main`、フォルダを **`/docs`** にして「Save」を押します。
   - **必ず `/docs` を選んでください。** `/ (root)` にすると、`coupons/` のクーポンデータまでサイトとして公開されます。
3. 数分後、同じ画面に表示される URL（github.com なら `https://<オーナー>.github.io/coupon-ledger/`）を開き、ツールが表示されることを確認します。
4. その URL をメンバーに案内します（導入手順 3-A）。

> - リポジトリを Private にしても、Pages のサイトまで非公開になるわけではありません。公開されるのは `docs/` の中身（ツール本体）だけで、クーポンデータやトークンは含まれません。
> - github.com の無料プランでは、Private リポジトリから Pages を公開できません（有料プランが必要で、その場合もサイトは誰でも見られる状態になります）。社内の GHES では、Pages が有効か、誰が見られるかをインスタンスの管理者に確認してください。
> - クーポンを確定（マージ）するたびにサイトの再公開が走りますが、ツールの中身は変わらないので影響はありません。

### 抽出の記録（`coupon-exports` ブランチ）
抽出の記録は、main とは別の **`coupon-exports` ブランチ**の `coupons/_exports/検定のid.json` に保存されます（初めて抽出したときに自動で作られます）。
- 抽出のたびに PR を作らずに記録するため、main とは分けています。
- **このブランチにはブランチ保護をかけないでください。** Rulesets を「すべてのブランチ」に適用している場合は、`coupon-exports` を対象から外してください。保護されていると記録が保存できません（CSV のダウンロードはできますが、「抽出の記録を残せませんでした」と表示されます）。
- 記録を見たいときは、GitHub でブランチを `coupon-exports` に切り替えて `coupons/_exports/` を開きます。

### 3. マージ後のブランチ削除
ツールがマージ後や取り下げ後に自動で削除します。
「Settings」→「General」→「Automatically delete head branches」もオンにしておくと安心です。

### 4. メンバーの追加
- 「Settings」→「Collaborators」→「Add people」で、メンバーの GitHub ユーザー名を追加します（Organization の場合は Team に書き込み権限で追加）。
- メンバーには「[導入手順](#導入手順発行できる状態になるまで)」を案内してください。
- 各メンバーのトークンに必要な権限は次のとおりです。
  - **classic token：** `repo`
  - **Fine-grained token：** Contents（Read and write）と Pull requests（Read and write）
